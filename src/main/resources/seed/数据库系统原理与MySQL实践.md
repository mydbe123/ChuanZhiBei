# 数据库系统原理与 MySQL 实践

## 关系模型与范式
- 第一范式（1NF）：属性不可再分。
- 第二范式（2NF）：消除非主属性对码的部分函数依赖。
- 第三范式（3NF）：消除非主属性对码的传递函数依赖。
- BC 范式（BCNF）：所有决定因素都包含候选码。
范式化减少冗余与更新异常，但过度范式化会增加连接开销，实际系统常在范式与反范式之间折中。

## 事务与隔离级别
事务的 ACID 特性：原子性（Atomicity）、一致性（Consistency）、隔离性（Isolation）、持久性（Durability）。
并发事务可能产生的异常：
- 脏读：读到其他事务未提交的数据。
- 不可重复读：同一事务两次读取同一行结果不同。
- 幻读：同一事务两次范围查询出现新行。
MySQL InnoDB 的四种隔离级别：
1. READ UNCOMMITTED：可能出现脏读。
2. READ COMMITTED：避免脏读，可能出现不可重复读。
3. REPEATABLE READ（默认）：通过 MVCC 与间隙锁避免不可重复读与大部分幻读。
4. SERIALIZABLE：串行执行，代价最高。

## 索引
- B+ 树索引是 InnoDB 的默认索引结构，非叶子节点只存键，叶子节点存放数据并用双向链表相连，适合范围查询。
- 聚簇索引：主键索引的叶子节点存放整行数据；二级索引叶子节点存放主键值，需要回表。
- 覆盖索引：查询列都包含在索引中，可避免回表。
- 最左前缀原则：联合索引 (a,b,c) 只能被 a、a+b、a+b+c 形式高效利用。
- 索引失效的常见场景：在索引列上使用函数或运算、隐式类型转换、以 % 开头的 LIKE、OR 连接非索引列、不符合最左前缀。
- 索引不是越多越好：会增加写入成本与存储开销。

## SQL 优化
- 使用 EXPLAIN 查看执行计划，关注 type、key、rows、Extra 字段。
- 避免 SELECT *，减少回表与网络传输。
- 分页深翻页（LIMIT 100000, 20）可用「延迟关联」或基于游标（WHERE id > ?）优化。
- 大事务拆分、批量插入使用 rewriteBatchedStatements、避免在事务中做远程调用。

## 锁
- 按粒度分：表锁、行锁、间隙锁（Gap Lock）、临键锁（Next-Key Lock）。
- 按模式分：共享锁（S）、排他锁（X）、意向锁（IS、IX）。
- 乐观锁通过版本号或时间戳实现，适合读多写少；悲观锁通过 SELECT ... FOR UPDATE 实现。

## 高可用与扩展
- 主从复制：binlog 同步到从库，可读写分离。
- 分库分表：垂直拆分按业务，水平拆分按数据范围或哈希；会引入分布式事务与跨库 JOIN 问题。
- 缓存策略：Cache Aside、Read/Write Through、Write Behind；需要处理缓存穿透（布隆过滤器）、缓存击穿（互斥重建）、缓存雪崩（过期时间加随机值）。

## 设计规范建议
- 主键使用 BIGINT 自增或雪花 ID，避免使用业务字段作为主键。
- 金额使用 DECIMAL，避免浮点误差。
- 字符串统一 utf8mb4，时间字段统一 DATETIME(3) 并明确时区。
- 为高频查询条件建立组合索引，为外键关联字段建立索引。
- 所有表包含 created_at、updated_at，重要业务表增加逻辑删除标记。
